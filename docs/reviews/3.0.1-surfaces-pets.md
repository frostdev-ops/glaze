# 3.0.1 surfaces and local pets: independent source review

Reviewed the B11 candidate from `daca26f` in the isolated release worktree. This review owns runtime fixes and regression probes; the release author owns the translation catalogues, release documentation, browser harness and acceptance evidence. Pet artwork is independently owned and was not edited here.

## Fixed findings

1. **P1 — Share Sessions could fail during startup.** Its HTML loaded `defaults.js` without the new shared surface schema. Added the dependency before defaults and checked every extension HTML entrypoint for this ordering. The popup also omitted the derived surface stylesheet, so writing surface variables there had no effect; its sheet is now loaded.
2. **P2 — Several backing surfaces escaped the shared model.** Fallback forms of palette variables remained in the sticker panel, pet habitat/dialog/selects, and sticky course-tab header. Popup inline fills and radii, editor inline borders/header blur, tab drag/notice shadows, and the isolated DocViewer toolbar also bypassed controls. They now consume the shared fills, border strengths, shadows and radius. The catalogue check includes inline editor/popup CSS and fallback variable syntax. Circular controls, semantic accent fills and document canvas pixels retain their roles.
3. **P2 — Gradescope's isolated bar ignored the stored Look.** The registered script now includes the existing settings dependencies and paints sanitized surface settings, palette and depth in its shadow host. Storage, device-mode and scheduled changes repaint it. Failed reads or an invalidated context close the bar. Revision/host checks reject stale async answers; existing switch rechecks and sequential authenticated reads remain in place, with no new network requests.
4. **P2 — Standalone Share Sessions did not expose configurable backing surfaces.** It now reads the same sanitized surface model with revision guards, safe failure behavior, device/schedule refresh and global radii. Its original light/dark role colors are retained as default fallbacks; explicit color/tint/frost/border/shadow/depth settings override them. The page has a solid ground, so custom opacity stays opaque. The existing CSP now permits only self/data images for the local frost texture; connect-src stays none. No sharing consent, key, relay or network behavior changes.
5. **P2 — Hidden/removing pets could keep listeners or resume unexpectedly.** A disconnected canvas and invalidated context now stop the player before hidden/offscreen early returns. Explicit sleep is separate from intersection visibility, so a queued intersection callback cannot wake a sleeping habitat. The habitat stops its midnight clock and listeners when its extension context is invalidated, including after a held profile/read.
6. **P2 — DocViewer could accept a stale same-file storage read or remount after invalidation.** A document-open generation now guards the initial annotation read, pending animation work is cancelled on close, and the mount pass requires a current key/context. An invalidated frame treats later parent messages as off. Sanitized depth, border, frost, custom color and shadow controls reach its native and shadow toolbars; turning Glaze off removes the shared sheet and theme.
7. **P2 — Pet mutation admission was broader than necessary.** Import/delete now require the exact top-level extension options origin. LMS callers remain limited to list/get for their confirmed site while Glaze and the pet switch are on. Unit probes cover forged origins, embedded editors, unconfirmed/cross-site LMS callers and disabled switches. The existing serial storage broker, image decode/re-encode, file/layout/frame bounds and read-failure preservation were retained.
8. **P3 — Malformed local package errors could expose untranslated parser/ZIP messages.** Explicit pet validation errors are marked as user-facing; other parser/decoder errors map to the existing translated package error. Dynamic import messages are included in the i18n used-key check. No new translation keys were introduced.
9. **P3 — Course tint inheritance missed some containers.** Corrected the custom card class to `.gz-course-card` and included Canvas planner groups and course-color markers so locally inherited course colors recompute the derived fills.

10. **P2 — Moodle color-only backing declarations omitted frost.** The author's custom Chrome probe showed a correctly colored/radiused native card with no grain layer. Existing panel, surface and band fills now layer the local frost image; existing large glass bars do too. No row backdrop filter is added. A failing-before regression probe covers the native card rule.
11. **P2 — The pet clock ignored Glaze Motion off.** The player now observes only the root's motion attribute and pauses/resumes its low-rate clock immediately. The extension UI paints the same motion attribute, so library demonstrations obey the global switch too. OS reduced motion continues to hold a still frame. A failing-before probe verifies off, requested state changes while off, resume and stop.

12. **P2 — Opening Settings eagerly decoded hidden pet atlases.** The library now mounts its import control immediately but defers the first list/image render until its own root becomes visible. A one-shot root observer is disconnected after visibility or pagehide; browsers without it retain the eager fallback. Failing-before probes cover the hidden initial state and leaving before visibility.

13. **Compatibility addition — Existing local app pets can contain extra trailing animation frames.** Imports now accept bounded, contiguous extra frames after each state's canonical minimum and derive counts from decoded alpha rather than metadata claims. Gaps, missing required frames, over-eight counts and opaque cells remain refused. Counts survive normalized storage/get and drive both frame addressing and one-shot durations. Literal `displayName` is accepted after `name`, while spritesheet paths remain ignored. Added builtin Rime (seven idle frames) and Glaze registry entries without touching their artwork. Synthetic decoded-alpha and normalization/broker regressions accompany the real Rime metadata fixture; the author's browser gate verifies the real atlas decoder.

14. **P2 — Scoped course Looks stopped at some palette boundaries.** Native course pages already apply the complete worn Look. The lazy DocViewer responder now sends that course's Look instead of global surface settings. Moodle's existing per-card Look painter now carries the surface model, radius and depth as well as its palette, explicitly clearing inherited global overrides for an owned Look. Its local fill/border/shadow roles are derived again in that scope. Unchanged passes still write nothing, and removing a course Look clears every owned variable. Ultra/Canvas/custom board cards have no separate owned-Look painter; they retain their existing root Look inheritance and local course tint.
15. **P3 — Classic outfits appeared editable while an animated character covered them.** The existing outfit label is hidden while a sprite is selected. Its saved outfit remains intact and the control returns when Classic is selected; no clothing fitting behavior is added.

## Verification

Failing-before probes reproduced detached/invalid hidden pet listener retention, stale intersection wakeups, habitat reload retention, missing DocViewer depth, stale same-file annotation reads, invalidated viewer repaint, missing popup stylesheet and non-solid editor opacity. Focused runtime, sender, settings, editor, session, surface, pet, i18n and viewer checks pass after the fixes. The new local import probes preserve storage on malformed ZIP/JSON and retain actionable size failures.

The first content scripts remain **Ultra 227,690 bytes; Canvas 204,643 bytes; Moodle 174,717 bytes**. No review fix adds first-script bytes. Measured `c30814e` totals are 225,195 / 202,148 / 172,222 bytes, so B11 adds 2,495 bytes per LMS. The Ultra guard now ratchets against the measured 225,195-byte release instead of the candidate total; the candidate fits that release plus 2%. Canvas/Moodle baselines remain unchanged. DocViewer is **34,997 bytes**, within its existing 34,317-byte baseline plus 2%; its small remaining margin should be respected. The existing performance guards pass: no new intervals, whole-page style reads or broad sweeps. Small rows gain no backdrop filter. The new schedule timers target the next actual boundary and stop on pagehide.

Serial full suite: **1,275 tests passed, zero failures** (`nice -n 15 node --test --test-concurrency=1`; `/tmp/glaze-b11-fresh-review-suite.txt`). The first pass exposed four stale Relay UI fixture assumptions; its browser/stylesheet stand-ins were updated and the complete suite passed on rerun. The subsequent narrow Sessions CSP and phone-preview fill changes passed focused surface/Relay UI checks. Final browser acceptance belongs to the release author.

## Evidence boundaries and remaining gates

The author's earlier real-extension default comparison reported 118/120 exact captures; the two Terminal outline cases differed by ten pixels each because fixed corners were corrected to respect the global radius. That comparison predates these review fixes and is not final browser acceptance. The author must rerun defaults and custom-surface/import/habitat/DocViewer gates against the reviewed runtime and final artwork.

Intentional additional changes outside the earlier default captures: Gradescope now wears the stored Look; drag/narrow-notice and DocViewer toolbar shadows use the model instead of fixed shadows. Native document page shadow geometry retains its default role while responding to depth/strength/color. Share Sessions retains its original role colors by default.

This source review does not establish authenticated LMS coverage, cross-browser image decoder behavior, publication, deployment or release readiness. No account was accessed, no release was pushed and no pet image was changed by this reviewer.

# B0: Blackboard Ultra spike on a real student account (read-only)

2026-10-15. One school's Ultra, a student account with four course memberships. Learn **4001.0.0 (rel.89)**, Ultra UI build **uiv4001.0.0-rel.37**. Shapes only: no values from the account
appear here or in the fixtures.

Each claim is marked **[M]** measured on the account, **[D]** documented (in Ultra's own shipped bundle or Blackboard's
docs), or **[I]** inferred.

## Verdict

**On this one account, every B-package looks feasible from GETs on the student's own session. The planning and grade
packages are measured; the document viewer, grading periods, dropped scores and Gradescope were not available to
measure.** One school and one student are one data point: see "What other schools may differ on" below.

- **Courses, terms, due items, grades and attempts:** all answered for this student. The private `/learn/api/v1` was
  richer than the public API every time it was compared. **[M]**
- **Submission state:** one request per course. Ultra's own course Grades page asks
  `gradebook/grades?expand=lastAttempt,submissionStatus,…`. **[M]**
  - The answer gives each row a `submissionStatus.status` (`GRADED` / `SUBMITTED` / `UNOPENED` seen; the bundle's enum
    has more), and the last attempt with its submission time (`attemptDate`) and graded dates. **[M]**
  - Classifying on time / late / missing / excused from these is **[I]**. One saved draft (`IN_PROGRESS`) was seen, but
    how to classify it wasn't validated; exemptions and Ultra's automatic zeros weren't present to test. B1 needs
    synthetic cases for all three.
- **The overall-grade formula: readable in the one course that returned an overall column.**
  - That course's overall column carried `calculatedFormula`: a weighted-category recipe (`wgt`, 15 categories, some
    excluded). **[M]**
  - Glaze's existing `GZ_GRADECALC.model()` reproduced Blackboard's own overall grade on that course, with zero
    discrepancy (`kind: 'weighted'`). **[M]**
  - Calibration receipt: 1 course with a formula, recipe kind `wgt`, element types `cat` only, modes `proportional`
    only, no drop keys, `running: true`, discrepancy 0. No course, id or score is recorded.
  - The other three courses returned no overall column to this student, so no formula was returned to them. **[M]** Why
    (no overall grade set up, or one hidden from students) can't be told from here.
  - This doesn't show that every visible overall column carries a formula Glaze can read. Points totals, dropped scores,
    single weighted items and free-form formulas exist in Ultra **[D]**, and `GZ_GRADECALC` already declines them, as
    it declines a recipe that fails calibration. **Decision 3's estimate path stays**: for courses with no formula, an
    unreadable one, or a calibration mismatch.
- **Ultra has a calendar feed** ("Share calendar" in Calendar Settings ⋯). **[M]** It wasn't opened, and Glaze
  shouldn't use it either: see B2.
- **No Gradescope** on this account (the LTI tools are a media tool, a publisher and tutoring). **[M]**
- **Document viewer: not identified.** No document with a file had been opened by the owner (progress state `None`
  on all eight checked), so by the brief's rule none was opened. **[M]** The bundle only shows Ultra's own
  `bb-file-viewer` inline preview and Bb Annotate strings. **[D]**
- **Page anchors:** stable ids, `analytics-id`, `data-*` and BEM-ish classes exist for every page visited. The
  `makeStyles*-N` and `muiltr-*` classes are hashed per build and must not be keyed on. **[M]**
- **Glaze already requests LTI credential fields:** Ultra's private contents API returns some LTI links' `secret`/`key`,
  and two existing Glaze features request it. They keep the fields in memory only. This is tracked for B1: see
  "Safety notes". **[M]**

## What other schools may differ on

All of these are **[I]**: one school, one student, Learn 4001.

- **Grade setup:** whether an overall column exists and is shown to students; its recipe (points total, drops, single
  items, free-form formula); grading periods; letter schemas.
- **Tools:** Gradescope or other LTI tools, and their credential mode (per-link credentials carry `secret`/`key`;
  domain-level ones didn't here).
- **Feature switches:** the calendar feed, progress tracking (`state` on content), automatic zeros for missing work,
  due-date exceptions, the new course navigation bar, and the Institution Page.
- **Limits and versions:** the To Do window limit, and Ultra's continuous updates (shapes, enums and hashed classes can
  change between releases).

## Ultra version and how pages change (item 1)

- **Version:**
  - Public `GET /learn/api/public/v1/system/version` → `{ learn: { major: int, minor: int, patch: int, build: str } }`
    answers for a student. **[M]**
  - The UI build is in `<base href>` (CDN path `…/ultra/uiv4001.0.0-rel.37_<sha>/`). **[M]**
- **Page model:** a single-page app, AngularJS 1.8.4 with React islands (`bb-todo.react-container`,
  `react-course-content-header`…), MUI v5 (`Mui*` classes) and JSS (`makeStyles*-0-2-N`). **[M]**
  - Clicking "Calendar" in the base navigation changed the URL and kept the document (a `window` marker survived). **[M]**
  - So `content.js`'s MutationObserver plus throttled `flush()` is the right model. There's no page load per route,
    and no route event Glaze can rely on. **[M]**/**[I]**
- **`<base href>`:** points at the CDN, so every fetch must be absolute (`location.origin + path`). Glaze's `api()`
  already does this. **[M]**
- **Writes Ultra makes on every page:** `PUT utilities/batch`, `POST /telemetry/api/v1/browser/interactions`, and on
  the stream and outline pages `POST /learn/api/v1/streams/ultra`. The spike's tab blocked the first two (it allowed
  only the stream POST, so the Activity page could load). Glaze needs none of them. **[M]**

## Per package

### B1: Ultra data layer — feasible [M]

- **Courses:** #2 with `GZ_COURSES` (already used).
  - Terms come from `course.term` (expanded inline) or #4.
  - Course color is `courseCardColorIndex % 10 + 1`, as today. The image is `course.banner.permanentUrl` or
    `bannerImageThumbnail` (absent when there's no banner).
- **Due items:** #5 for the next week. Ultra caps its window at 15–20 days, so ask in 14-day slices if more is needed.
  #6 covers longer windows, with discussions (`Engagement`) and LTI items.
  - Both join to the gradebook by column id: `column.id` in #5, `itemSourceId` in #6. In a second read, all 45 calendar
    items joined a gradebook column, `Engagement` items included. **[M]**
  - A graded discussion appears twice in #6 (a `GradableItem` and an `Engagement`, same id): dedupe by id. **[M]**
  - The join is measured on this account only. If an item joins no column, keep it as a calendar entry without a
    grade state, and never match by title. **[I]**
- **Submission state:** #10, one request per course (page it: Ultra's page asks 25 at a time; `limit=200` worked for
  Glaze's #9).
- **Grades:** #9 plus #16 (its letters; cut-offs only where it sends bounds, see #16).
- **Before reusing the private contents callers:** fix their LTI-field retention (see Safety notes).
- **Status:** the fixtures carry the shapes. `test/ultra-fixtures.test.js` checks they read with today's `GZ_COURSES`,
  `GZ_DUE_WEEK`, `GZ_PAGE.overall`, `GZ_GRADECALC.model` and `GZ_GRADES.awaiting/late`.

### B2: Planning — feasible [M], with notes

- **Types and time zone:** due items are Ultra assignments and tests (`resource/x-bb-assessment`; the calendar calls
  both `eventType "Test"`), graded discussions (`resource/x-bb-forumlink`, `Engagement`), and LTI items (`ltiDomainId`
  set, no `scoreProviderHandle`, `eventType "Manual Grade Column"`). Dates are UTC; the student's time zone isn't in
  `users/me`, so render in the browser's. **[M]**
- **What To Do lists:**
  - For assessments, every item in To Do had no grade status yet. **[M]** Inferred: Ultra drops submitted work.
  - Two LTI items were listed although graded. **[M]** So Glaze's own "done" must come from #10, not from To Do
    membership.
- **"On time / late / missing / excused":**
  - On time / late: the submission time is `lastAttempt.attemptDate`. Compare it with `column.dueDate`, minus
    exceptions (#18), as `GZ_GRADES.late` does. **[M]** for the fields; the rule is **[I]**.
  - `attemptReceipt.submissionDate` equalled `attemptDate` wherever both were present, but a receipt is often missing.
    **[M]**
  - Ultra has no explicit late flag in the data. **[M]**
  - Missing: due date passed and `submissionStatus` `UNOPENED`/`NOT_SUBMITTED`, or Ultra's own `PAST_DUE_AUTO_ZERO`
    (enum in the bundle; one course shows a "past due zero" tooltip). **[D]**
  - Excused: `isExempt` / `EXEMPT`. The field is **[M]**; no exempt row was present to test.
  - An `IN_PROGRESS` attempt is a saved draft, not a submission. One was seen **[M]**; its label is **[D]** ("Draft
    Saved" in Ultra's strings).
- **Link back to an item:** `column.contentId` + `courseId` → `/ultra/redirect?redirectType=nautilus&courseId=…&contentId=…`
  (the public contents API gives exactly this as the item's `alternate` link). **[M]**
  - Not followed for tests: it may open the assessment page. **[I]**
- **Calendar link:** Ultra offers students "Share calendar" (Calendar → Settings → ⋯). **[M]**
  - **Recommend Glaze not read or generate it.** GET fetches the existing feed URL and POST regenerates it [D]. A first
    GET may well create a token server-side [I], and the URL is a bearer secret.
  - Glaze's own .ics export from #5/#6 covers the need. A student can still paste Ultra's link into the class-schedule
    import themselves.
- **Risk:** the To Do window limit, and the bundle's long status enum (handle unknown values as "not done").

### B3: Search inside your courses — feasible [M]

- **Content:** public #19 (recursive, with document `body` HTML and file names) answers for a student. So do private and
  public announcements (#21) and public discussions (#22, topic lists with the opening post).
- **Opening a result:** each content item's `links[0].href` is Ultra's own open-in-UI address.
- **Risks:**
  - Public #19 includes items the student may not reach yet (`availability.adaptiveRelease`). Filter on
    `availability.available === "Yes"`.
  - **Use the public contents API for search, never the private one.** Private contents carry per-link LTI
    `secret`/`key` (Safety notes). **[M]**

### B4: Grades — feasible on this account [M]; elsewhere depends on each course's setup [I]

- **Can a student see the overall-grade formula?** In the one course here that returned an overall column, yes. Other
  courses and schools may differ (see the verdict).
  - That row in #9 (and #13) carries `column.calculatedFormula = { isTotalCalculation, aliases{c_N → categoryId},
    formula }`.
  - `formula` is MathML wrapping `@X@BBCalColElem(wgt:{ weights:[{ element:{ type:"cat", alias, mode:"proportional",
    exclude_list?[{exclude_alias}] }, weight }], running })@X@`. Weights sum to 100.
  - Measured: 15 category elements, some excluded at weight 0 by self-exclusion, `running: true`.
  - Glaze's `GZ_GRADECALC.model` reproduced Blackboard's figure on that course (discrepancy 0). **[M]**
  - Keep the existing unsupported and mismatch paths. **[I]**
  - The overall row's `displayGrade.score` is the **percent**, and `effectiveScore / pointsPossible` is the same share
    in points (`column.possible` is not 100). **[M]**
- **Drops, weights, what counts:**
  - Ultra's overall-grade panel can drop lowest/highest N per category (`dropLowestNScores`…). **[D]**
  - Not seen in a formula here; Glaze already reports unknown element keys as unsupported. **[M]**
  - "Counts toward the overall" per item = public v2 `includeInCalculations` (#14). **[M]**
- **Courses with no overall grade column returned (3 of 4 here):** no formula was returned to this student. **[M]**
  What-if uses points, labelled (decision 3's fallback).
- **Graded dates for a term trend:**
  - `lastAttempt.attemptFirstGradedDate` / `attemptLastGradedDate` (#10/#11).
  - `lastOverrideDate` and `lastGradedDateViaLtiAgs` on rows graded without an attempt.
  - Grading periods: public #17 empty here; handle `[]`. **[M]**
- **GPA and past terms:** the overall percent per course plus `course.term`. **[M]**
- **Syllabus import:** no syllabus tool; a syllabus is an ordinary document or file found through #19. **[M]**/**[I]**

## Decision 1: where the Dashboard features live on Ultra

Screenshots of each, with a dashed placeholder drawn only in the spike's own tab, were given to the owner. They aren't
committed.

1. **A panel on the Courses page, in the right column above Ultra's To Do** (`div.todo-panel`, prepend).
   *Recommended.*
   - It's the page students land on.
   - Better To Do sits beside Ultra's own To Do instead of hiding it.
   - Notes and widgets get a compact column.
   - Collapsible like Ultra's own To Do sections.
   - **Variant A2:** a full-width strip above the course cards (`.courses-panel`, prepend). There's more room for
     widgets, but it pushes the courses down.
2. **A section on the Institution Page**, under its banner.
   - The page is a dashboard of sorts.
   - But it's the school's page, partly in a cross-origin iframe, and fewer students open it.
3. **A Dashboard page of Glaze's own**, opened from Ctrl+K (and optionally an entry in the base navigation).
   - Full width and no crowding.
   - But it's one click away, and an added nav entry is the most intrusive change to Ultra's chrome.

## Safety notes for the B-packages

- **Read only what's needed:**
  - **LTI credential fields in private contents.** **[M]**, presence only; no value was read or kept, and whether
    the strings are usable credentials wasn't tested.
    - Ultra's private `GET /learn/api/v1/courses/{c}/contents` and `…/contents/{id}/children` return
      `results[].contentDetail["resource/x-bb-blti-link"].secret` and `.key` on a per-link-credential LTI item (1 of 8
      LTI items here).
    - Every variant tried carried them: no query, `?limit=200`, `@view=Summary`,
      `fields=id,title,contentHandler,contentDetail`, and nested slash-key projections such as
      `fields=…,contentDetail.resource/x-bb-folder.isBbPage`. That last one returned the whole `contentDetail`.
    - **`@view=Summary` and nested slash-key `fields` are therefore not fixes.**
    - A `fields` list without `contentDetail` returned neither field. So did one naming whole handler objects
      (`contentDetail.resource/x-bb-folder,…`), but that one dropped `isBbPage`, so it's no use either.
    - Public v1 `contents` (with or without `fields`) never had them.
    - Ultra's own outline requests `@view=Summary`, so the student's browser already receives these fields from Ultra
      itself.
  - **Glaze's existing callers** request private children with no view:
    - `features/download.js` (`list()`, `…/children?limit=200`) holds each answer only during the Download all walk. It
      keeps selected file metadata and bytes, not the item objects.
    - `features/previews.js` (`children()`, bare `…/children`) keeps the full results, `contentDetail` included, in its
      in-memory `peeks` Map for the page's life. Its 60 s check is only about freshness.
    - Neither writes them to `storage`, IndexedDB, the console or a zip (per source and the Codex review).
  - **Tracked for B1, before either caller is reused:**
    - Project items to the fields actually used before caching: previews needs id, title, state and due date, not
      `contentDetail`.
    - Take `isBbPage` from the public contents map `content.js` already builds (`contentHandler.isBbPage`), not from
      private `contentDetail`.
    - Request private children with a `fields` list that leaves `contentDetail` out, and add a shape test proving Download
      all still finds files from what remains (`body` and file data). Keep its unopened-item handling.
  - The public contents API's tests carry `password.enabled` only (no password). **[M]**
- **Ultra makes its own writes** (`PUT utilities/batch`, telemetry POST, stream POST). Glaze should only ever add GETs,
  as today.
- **Discussions and announcements:** listing them (#21, #22) returns `isRead` and doesn't mark anything read. Opening a
  thread or an announcement in the UI would. **[M]**/**[I]**

## Method and budget

- **Access:** the owner's separate, signed-in Chrome at `127.0.0.1:9333`, through Playwright `connectOverCDP`.
  - Each run opened one background window of its own off-screen and closed it at the end.
  - The owner's tab was never touched.
- **Writes:** every non-GET from the spike's tab to the LMS was aborted, except Ultra's own `POST /streams/ultra` on the
  Activity and outline pages.
- **Clicks:** none submitted, posted, marked reviewed or changed settings. Only these were clicked:
  - "Calendar" in the base navigation (for the SPA test).
  - Calendar Settings and its ⋯ menu (to read the item labels).
- **Pages opened:** course list, Institution page, Activity, Calendar, Grades (all and two courses), and two course
  outlines.
- **Not opened:** no test, assignment, discussion thread, message or content item.
- **Requests:**
  - 138 GETs by the spike itself (at ≤ 1 per 1.1 s), plus about 50 in two follow-up checks after review: one for the
    LTI field provenance, one for the calendar join and the attempt date order. Both were presence and counts only.
  - About 20 page loads, whose own Ultra traffic was roughly 400–450 more requests.
  - Overall about 550–600: a little over the ~500 guideline, mostly Ultra's own page traffic.
- **Personal data:** raw answers and screenshots stayed in the scratch folder and are deleted after this package.
  Before committing, the diff was grepped for the owner's name, email, school host, course codes and real ids.

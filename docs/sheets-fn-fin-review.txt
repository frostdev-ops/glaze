DECISIONS AND LIMITS
- Actual range errors propagate for NPV and SUMSQ, despite ambiguous/contradictory support-page wording.
- Nonzero ordinary annuity type values act as 1; cumulative functions require exactly 0 or 1.
- PMT nper=0 is #NUM!; NPER with rate=0/payment=0 is #DIV/0!. Cumulative end>nper is #NUM!.
- DB truncates month, rounds its rate to three decimals, accepts a positive period below 1 as first period,
  and allows an extra period only for a partial first year. Its geometric form avoids a user-sized loop.
- DDB's fractional period/factor and salvage clamp, SYD bounds, EFFECT/NOMINAL domains matched probes.
- RATE's published 20-step rule does not describe a 20-step Newton implementation of its annuity equation:
  live Excel succeeds on cases that needed 24, 37, 83, 119 and 131 such steps. Glaze now bounds a safeguarded
  Newton search at 144 steps and checks the remaining balance, matching the recorded success/failure cases.
  This budget is an implementation decision, NOT a claim to have reconstructed Excel's private algorithm.
  Exact success/failure parity for arbitrary guesses remains unproven. IRR keeps 20 steps and XIRR 100.
- XNPV uses #NUM! for invalid/nonnumeric schedules (all blank values are #VALUE!); XIRR uses #VALUE!
  for nonnumeric schedules, but an all-blank values range is #NUM!. Rates <=-1 are invalid for XNPV;
  guesses <=-1 are #VALUE!. MIRR finance=-1 works when every actual outflow is at period zero.
- FLOOR(nonzero,0) is #DIV/0!, CEILING/MROUND with zero significance are 0. Fifteen-digit multiple rounding,
  LOG(125,5)=3, invalid DECIMAL radix=#NUM!, and ROMAN's 0–4 / TRUE / FALSE forms were retained.
- AGGREGATE 1–13 rejects calculated arrays; reference options 0–7 match the recorded error/hidden/nested
  combinations. Native filtered-row probes show even options include filtered rows and odd options skip them.
- FIND/SEARCH/REPLACE use current compatibility-version-2 character positions. FINDB/SEARCHB retain UTF-16
  positions in Glaze's fixed SBCS policy. SEARCH's ? still consumes UTF-16 units, with valid starting boundaries.
  SUBSTITUTE has literal matching. SEARCH ignores a trailing ~ and treats ~ as an escape before any character.
- TEXTSPLIT supports multiple delimiters, longest overlap, match_mode, ignore_empty and scalar padding.
  All-empty output is #CALC!, invalid/empty input is #VALUE!. The engine already accepts C.err('#CALC!').
- CHAR/CODE deliberately remain Windows-1252 on every host for portable workbook results. Mac Excel's
  Macintosh mapping differs (the exact native results are below). This is a documented product choice.
- CLEAN follows Microsoft's documented ASCII 0–31 set on every host. Native Mac Excel also strips U+0080–009F;
  Glaze deliberately retains that additional set, including the six characters Microsoft says CLEAN leaves intact.
  PROPER apostrophes/digits, TEXTJOIN empty arrays, FIXED rounded negative zero, NUMBERVALUE exponents,
  and FIND empty-target behavior were settled by the probes below.

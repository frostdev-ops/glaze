## Detailed description

Make Blackboard Ultra, Canvas and Moodle feel like yours. Glaze restyles your courses with palettes, fonts, backgrounds and motion, and adds tools for planning and studying right where you do your coursework. It works at any school using Blackboard Ultra, Canvas or Moodle, including on a school's own domain once you allow it. No account, no analytics. Your courses, grades, notes and tasks stay on your device; your settings follow your browser's sync if it is on; sharing is optional and encrypted.

PRIVACY

No analytics, no ads and no account. Settings stay in your browser and follow Chrome or Firefox sync if it is on (they include course nicknames, GPA choices and some school/course/account identifiers; Safari keeps them on the device). Course details, grade records, notes, tasks, your place, the due list and typing backups stay on your device. Glaze reads your own Blackboard, Canvas or Moodle site using your existing session, and writes to it only when you ask (a planner tick, a Canvas nickname or color, Sign out, Moodle's Edit mode). Chosen web fonts and background images make ordinary network requests; linked videos and animations are fetched by Glaze's worker without cookies, a referrer or redirects (12 MiB video, 6 MiB picture, 1 MiB Lottie; video/picture sides up to 4096 pixels). Identifying metadata is removed from the file’s container; encoded streams and visible pixels remain. Files saved before 3.3.5 that cannot be cleaned stay on this device and are not shared. Course tab sketches stay in memory and are never sent anywhere. Share sessions and mod channels, only if you use them, send encrypted content that the relay cannot read. Glaze does not collect or sell your coursework, grades, credentials or browsing history. A mod granted course data and network access can send that data to its granted hosts. ## Single-purpose statement

Glaze customizes how Blackboard Ultra, Canvas and Moodle pages look and read, and helps users plan and keep their own coursework on those pages. Its themes and optional helpers present the user's existing course information, keep the user's own tasks, notes and drafts locally, and save accessible files the user chooses. Every permission serves that purpose.

## Permission justifications

### storage

Saves theme and extra settings in chrome.storage.sync, including user-set course nicknames, colors, tint and Looks; these follow Chrome sync when enabled. Local storage keeps course details, seen-grade and content records, the due list, Better To Do's own tasks and plans, the class schedule, reminder and streak state, widget layouts, hidden folders, supported draft backups, what-if scores and course positions, and the sites the user approved. Course tab sketches (a page's boxes and colours, no images) are kept only in chrome.storage.session (memory). Canvas badge records include site, account and course identifiers; some Ultra seen-grade/content records still use course ids without account scoping. Drafts expire after at most 14 days; switching backup off deletes them. Coursework records and draft text are not synced. See the privacy policy for each record's retention and removal behavior.

### unlimitedStorage

Notes, their pictures and attachments, course-card pictures and files kept for Look backgrounds are kept in the extension's own storage. This permission stops the browser from deleting them to free space. Nothing more is collected or sent because of it.

### Host access (1,000 character maximum)

Glaze themes Blackboard Ultra, Canvas and Moodle and adds study tools. Required hosts are only their hosted domains (*.instructure.com, *.blackboard.com, *.moodlecloud.com) and Glaze's gallery and share relay (frostdev.io, share.frostdev.io). A school's own LMS domain is added one site at a time with chrome.permissions.request, after the user clicks Use Glaze on the site in the popup, or Allow on the first-run page or in Settings; Glaze checks it is Blackboard, Canvas or Moodle and hands the grant back if not. https://*/* is optional only, for this and for All sites on the first-run page, after which Glaze asks the user first on each new school's pages. Other optional hosts are asked for when a feature needs them: a file server for Canvas Download all, Gradescope, a Look's media host, a mod's granted host, a custom share relay. On allowed sites Glaze reads with the user's session and writes only on their click (planner ticks, Canvas nicknames and colors, Sign out, Moodle's Edit mode).

### activeTab

When the user opens Glaze's toolbar popup, Glaze reads that tab's address and checks its markup for Canvas, Blackboard Ultra or Moodle with a packaged function, so the popup can offer to turn Glaze on for that site. It reads nothing beyond that check and keeps nothing unless the user allows the site.

### declarativeContent

Puts a dot on Glaze's toolbar icon on pages that look like Canvas, Blackboard Ultra or Moodle, with page-URL and CSS rules that Chrome evaluates itself, so the user can see where Glaze can be turned on. Glaze is not told which pages match.

### scripting

Registers Glaze's packaged content scripts on the sites the user allowed, so later visits are themed from the start, and runs the popup's LMS check in the current tab. With All sites granted, it also registers a packaged check that reads only a page's head. All code is packaged; nothing is fetched and run. It does not inject Glaze's theme into unrelated sites.

### Web-accessible resources

The theme stylesheets (theme.css, motion.css, extras.css, canvas.css, moodle.css, features/apps.css, features/lookx.css), bundled fonts, logos, stickers, pointers and pet sprites provide the theme in the page. lib/scene.js and the bundled lib/three.min.js draw animated backgrounds, and lib/scene-media.js with the bundled Lottie player (lib/lottie/) plays a video or animation behind the page. reader.html opens a file the user imports, and reads only with a one-use pass from Glaze's worker. Chrome requires these packaged files to be web-accessible to load them into LMS pages.

## Remote code (1,000 character maximum)

All of Glaze's own code ships in the package. The only code not in it is user-installed mods (Chrome only): JavaScript from a mod bundle the user chooses to install from a file, link, code or the Glaze gallery, or a signed update from the same author for a mod the user follows. Glaze never downloads code of its own to run. Before installing, the user sees what the mod may read and why, and approves it. Mod code runs only in the extension's manifest sandbox page, isolated from the LMS page, with no extension APIs and no cookies. Mods that read courses, to-dos or grades run in a Worker with no page of their own and reach the network only through Glaze, to HTTPS hosts that are declared and granted. A mod without data access may have a frame UI that can contact other sites. Updates must come signed from the same author and ask again for more access, and a signed blocklist can turn off harmful mods. Firefox and Safari builds run no mod code.

## Data usage (privacy practices tab)

Glaze has no analytics and does not sell user data or use it for unrelated purposes, creditworthiness or lending. Optional share sessions and mod channels send encrypted content to the selected relay. The optional signed blocklist sends a fixed credential-free GET without student identifiers. User-installed mods and linked media may contact other hosts as described above; a mod granted personal data and network access can send that data to its granted hosts. These services receive ordinary connection information such as an IP address. Keep the store's data-use answers consistent with these behaviors and PRIVACY.md.
